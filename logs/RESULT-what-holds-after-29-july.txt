AND ONE RESULT REPLACES THEM, stronger than what it replaces: THE PIPELINE IS DETERMINISTIC
END TO END. The two post-edit draws are independent — separate generations, separate

    THEREFORE, and this is weaker than the version written at 15:58: "the control arm

What survives of that morning's work: a redraw faithfully REPRODUCES whatever the spec
produces — v5 and v5-2nd agree to the character, including the fix loop's own mistakes. That
is a durability finding. "Quantities degrade across redraws" is not.

⚠️ AND THE CLEAN COMPARISON HAS NOT BEEN RUN. Isolating the spec edit needs two draws whose
trees are provenance-matched — either both converged on deterministic fixes alone, or both

(chain4). The import-path result survives because it uses round-1 output, and the control arm
running now was designed the same way for the same reason.


V. TWO PIPELINE DEFECTS, MEASURED
----------------------------------
⚠️ CORRECTED 16:52 — an earlier version of this section said "the loop repairs the wrong
side" and that it "spent seven rounds editing internal/api handlers". Both are withdrawn. The
per-round fix targets say otherwise and are quoted in full in
FINDING-twelve-lines-in-one-entry-broke-three-other-files.txt.

THE LOOP REPAIRS THE RIGHT FILE AND CANNOT FIX IT — then widens anyway.
    round 1   projects_test.go
    round 2   projects_test.go, THEN response/middleware/tasks/projects/router (widened in)
    rounds 3-6  projects.go only
It identified projects_test.go correctly and repaired it twice. Neither number moved: seeds
stayed 1, the assertion stayed 2, first observation through final tree.

THE WIDENED REPAIR MANUFACTURES DEFECTS. The mirrored `status` argument appears in chain5
with the edit reverted, so it belongs to the loop, not the spec. It was introduced by round
2's widening and then consumed rounds 3-6 entirely.

    So the original test-side failure got two attempts out of seven, and four rounds went to
    damage the loop had caused itself. That is worse than misattribution: a loop pointed at
    the wrong file can be pointed at the right one; this one was already there.

⚠️ THE cannot-FAIL / cannot-PASS TRIGGER IS NOT ESTABLISHED. It read:
    cannot-FAIL (asserts 1)  passes silently, ships, artifact survives   <- chain4
    cannot-PASS (asserts 2)  fails loudly, triggers widening, tree dies  <- chain5
The two shapes are real and the asymmetry between them is real. What is NOT established is
that a redraw chose between them. chain5's round 1 failed to COMPILE, so its twins were first
observed in round 2 — after that file had taken a deterministic fix, a drained-body rebuild
and a model rewrite. chain4 took only a deterministic fix and converged. (1,1) versus (1,2) is
therefore not a comparison of two draws, and chain5's as-drawn values are not recoverable from
any log. A within-draw round-1 rewrite explains the difference at least as well.

A REPEATED ERROR SURFACE IS A PERFECT PREDICTOR: 127 detections, 0 recoveries. The builder
already computes it and only acts past the flat budget. The four-word fix is NOT licensed by
that number — it was measured with a different signature — and logging was added so the next
corpus can answer it properly.
