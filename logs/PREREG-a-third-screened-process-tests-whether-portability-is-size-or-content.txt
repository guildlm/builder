WHAT IS ACTUALLY OPEN
    After 10 August exactly ONE claim survived a second screened process:

        BIG edit to the declaration line (+51, shipped)  -> LONG on 2 of 2 screened processes
        SMALL edits to the same line (+5, +13, +14)      -> disagree between p1 and p2, in
                                                            BOTH level and direction

    That split is the campaign's only portable result, and it rests on n = 2 processes and on
    ONE big edit. Two different things could be producing it:

        SIZE     — a large enough rewrite of the line flips any screened process, whatever it says.
        CONTENT  — this particular rewrite (`var ErrX`, "Exported sentinels", "(each errors.New)")
                   carries something the small ones do not.

    These are separable with an arm I already have: the PURE PARAPHRASE, +20, which adds no
    information whatsoever (byte-identical name list, no `var`, no "exported", no errors.New).
    It flipped p1. It has NEVER been run on a second process. If it is portable, the surviving
    distinction is about size/location and the shipped wording is one member of a family; if it
    is not, then something in the big edit's CONTENT is doing work that +20 of paraphrase cannot
    do — which would be the first evidence for content in a week that killed eight content
    accounts.

PROTOCOL (both gates unchanged, in this order, no exceptions)
    1. Probe fresh processes with specs/ledger-origorder-baseline.yaml until one returns ABSENT.
       Max 10 probes. LONG is uninformative; ABBREVIATED-at-baseline is informative under the
       standing definition but DISCARDED here for the same reason as 10 August — the ladder
       measures movement from an ABSENT baseline and cannot be read from halfway up the scale.
       Every probe, kept and discarded, goes in logs/PROBE-LEDGER.txt.
    2. SCREEN the ABSENT process with specs/ledger-ownplacebo.yaml (+54 rendered, content-free,
       same purpose, LARGER than every treated arm below). A process that flips is DISCARDED
       and recorded. Only ABSENT-at-baseline AND screen-null may host arms.
    3. On the eligible process, RESTART=0 throughout, IN THIS ORDER:

           base (= the probe from step 1) · screen +54 · shipped +51 · paraphrase +20
           · L4 +5 · L5 +13 · L6 +14 · base-close

       The two PORTABILITY arms run FIRST, before the ladder, because they are the primary
       question and a session can end early. Order is believed inert (p1 carried 26 draws with
       three byte-identical baselines at start/middle/end); base-close is what checks it here.

    Rendered purpose deltas, verified by tool before this file was written, and every arm passes
    _spec_pair_guard.py against the baseline at internal/models/models.go only:
        ownplacebo +54 · origorder (shipped) +51 · sentinelline-placebo (paraphrase) +20
        linedose-4 +5 · linedose-5 +13 · linedose-6 +14

AMENDMENT 1 — written after the eight registered arms, BEFORE either arm below is drawn
11 August, pid 4691 still alive and still eligible.

WHY. The registered series landed on the SIZE/LOCATION branch: the pure paraphrase (+20, adds
no information) flipped this process exactly as the shipped +51 did, and wrote the same third
byte sequence it writes on p1. But paraphrase and shipped differ in size as well as content, so
"size/location beats content" is so far supported by arms that are not size-matched.

Two arms I already have make a SIZE-MATCHED pair that differs ONLY in location:

    A+C  +21   ON the declaration line, bare names, no `var`  (LONG on p1)
    below +21  ONE SENTENCE BELOW the line, mentions ErrInvalid (ABSENT on p1)

Running both on pid 4691 completes the location x size 2x2 at MATCHED SIZE on a second
independent screened process, with the null half included rather than assumed.

ORDER: A+C first, then below-line, then a second base-close. RESTART=0 throughout.

BRANCHES
    both as predicted -> at matched size, an edit ON the line flips and an edit one sentence
        BELOW it does nothing, on two independent screened processes. LOCATION is doing the work

        substantially", with the shipped wording only one member of the family.
    A+C null -> size alone does not carry it: paraphrase and shipped share something A+C lacks,
        and the content account comes back at that size. Report as a MISS of the size account.
    below-line flips -> the location claim fails on this process; the screen's meaning narrows to
        "the same paragraph is not enough" and today's headline must be re-labelled p1-only.

AMENDMENT 2 — written BEFORE the redraw, after base-close-2
11 August, pid 4691, three baselines now byte-identical (base, base-close, base-close-2).

WHAT HAPPENED. The size-matched pair split the wrong way for the location account:

    A+C   +21  ON the line          LONG        ef8c15d6   (registered 0.75, HIT)
    below +21  ONE SENTENCE BELOW   ABBREVIATED cb873e76   (registered 0.80 ABSENT, MISS)

On p1 that below-line arm was ABSENT — it is the arm that KILLED "any line mentioning a
sentinel" on 10 August. Here it moves this process one step up the three-valued scale. So the
off-line null is itself process-dependent, and "editing other sentences does nothing" is false
at three-valued resolution on this process. That is a bigger correction than a level flip on a
small on-line edit, because the off-line nulls are what the location claim RESTS on.

REDRAW, because a surprising arm that is not redrawn is a story. RESTART=0, same process.
    P(below-line +21 redraws ABBREVIATED, byte-identical cb873e76)   = 0.80
    P(it comes back ABSENT — i.e. the first arm was not reproducible) = 0.15

    reproduces   -> the off-line partial effect is real on this process and the location claim
        must be restated at three-valued resolution: only ON-LINE large edits reach LONG, while
        off-line edits are NOT inert and can move a process halfway.
    does not     -> this process is not deterministic within a session, which would VOID every
        arm drawn on it today and is the most consequential outcome available here. It would
        also retro-question p1 and p2, whose determinism was inferred from redrawn arms and
        byte-identical baselines rather than from a redraw of every arm.
