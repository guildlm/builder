WHAT WAS BUILT IN RESPONSE — _asdrawn_diff.py, and it flags its own false null
The ad-hoc snippet is replaced by a named tool with a self-test. It compares snapshot to
snapshot on EVERY file (not just the ones no fix loop touched, which is all _untouched_diff.py
can reach), then compares FUNCTIONS inside every differing file, then reports what changed
OUTSIDE every function. When every differing file is the target but a function is collateral it
prints "THE FILE-LEVEL VERDICT WAS A FALSE NULL" rather than leaving a reader to notice.

    Three things it caught in ITSELF while being built, each of which would have produced a
    wrong published number:
      * comparing function BODIES only reported store.go as "0 of 9 differ" while that file had
        lost 421 characters. Renaming a receiver type changes nine signatures and no body. The
        span now starts at the `func` keyword.
      * with signatures included, a PURE rename read as "changed" — destroying the very
        distinction this arm turns on. Declared renames are now collapsed to a placeholder on
        both sides before comparison.
      * a change entirely outside every function was being folded into "none". There is now a
        residue pass, and a comment-only change must not trip it.

    It also REFUSES a snapshotless pair rather than falling back to the trees on disk, and says
    why: those are post-repair, and reading a repaired tree as a draw is the error behind every
    retraction on 29 July.
