METHOD NOTE — I CONTAMINATED A CORPUS ARTIFACT AND THE FILE-SET MATCH CAUGHT IT
================================================================================
While checking whether taskflow-v4 was green I ran `go build ./... && go test ./...` INSIDE
generated/taskflow-v4. `go build` writes its binary to the working directory, so it left an
8.2 MB executable named `taskflow` in a tracked corpus artifact.

    It was caught minutes later because the census's new file-set matcher stopped finding
    taskflow's log: the tree had 16 files and every candidate log generated 15. An ad-hoc
    script run BEFORE the contamination had matched; the census run AFTER it did not, and the
    disagreement between two runs of the same question is what exposed it.

    Removed. The tree is back to 15 files and the match is restored.

THE LESSON IS ALREADY IN THIS REPO AND I DID NOT APPLY IT. `_teeth_suite.verdict_for` copies a
tree to a tempdir before touching it, and BOTH `_escalation_surface.py` and `_gate_audit.py`
carry an explicit `# drop stray compiled binaries` cleanup — three tools that already know
building in place pollutes an artifact. A greenness check is a measurement, and measurements go
on a copy.
