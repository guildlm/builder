          taskapi/internal/config/config.go — "Treat an EMPTY env var EXACTLY like an UNSET one"

      `var EXACTLY` reads the ENGLISH noun "var" as a Go declaration, and config.go would have been
      told it must declare EXACTLY. Guarded by keeping MixedCaps names only (Go exported
      identifiers are MixedCaps; an all-caps token in prose is emphasis or an env var name). That
      removes EXACTLY and nothing else — the 125-tree numbers are unchanged at 63/1 and the spec
      directory now has zero over-claims. Residual, unfixed: "env var Timeout" would still be
      misread. No spec writes that today.

      A check calibrated to the subset it was designed on. Third time this campaign.

    WHAT FIX 2 ALSO CHANGES, AND HAS NOT BEEN MEASURED. `_required_decls` feeds two generation-path
    call sites, and both subtract sibling_decls first: a candidate is rejected for omitting a
    promised symbol only when NO sibling already declares it. So the new symbols bite exactly when
    the file is generated BEFORE its sibling has taken the job — which is the swapped-order arm.
    That is the intended direction and it is UNMEASURED; it needs a draw, and no draw was spent
    here. Stated so it is not later mistaken for something this session verified.

    take-EMPTY and looks perfectly plausible. A corpus-wide ratio is only as good as the join that
    built it, and this one was one rule away from a number I could not have caught by inspection.
