FINDING — two teeth-registry mutations produce Go that does not parse, and were scored CAUGHT
==============================================================================================

17:42 on 29 July. Found by asking a question that turned out to have the opposite answer to the
one expected, which is the second time today that has been the productive route.

THE QUESTION. `verdict_for` returns CAUGHT whenever the mutated tree's `go test` exits
non-zero. `go test` exits non-zero on a BUILD FAILURE exactly as it does on a failed
assertion. So: does the corpus ever credit the TEST SUITE with a kill that belongs to the
COMPILER?

THE ANSWER FOR THE SWEEP ROWS: NO, and that was worth establishing rather than assuming.
The 109 CAUGHT rows in the v5 sweep are dominated by status-code swaps, boundary flips, json
tag renames and `%w -> %v` — all constant or operator substitutions that cannot fail to
compile. The one deletion-shaped family, "drop <header>", is generated by `_hole_hunt`'s
header_rows, which REPLACES the line with `// MUTANT: header dropped`. Measured on
ratelimit-v4 and -v5: build=0, test=1. The tree compiles and the TESTS catch it. Correct.

THE ANSWER FOR THE HAND-WRITTEN REGISTRY: two entries are broken.
Ran every one of `_teeth_suite.MUTATIONS`' 34 entries against its v5 tree and compiled the
result:

    26  compile cleanly
     5  NOAPPLY (code moved; already reported honestly by the existing verdict)
     3  DO NOT COMPILE

    eventbus   bus.go        SYNTAX ERROR  ./bus.go:42:23: unexpected { at end of statement
    ratelimit  middleware.go SYNTAX ERROR  ./middleware.go:22:3: unexpected newline in
                                           argument list; possibly missing comma or )
    ledger     store.go      type error, and only on -v5, whose artifact is BASELINE-RED anyway

Both syntax failures reproduce on BOTH generations. Their `_drop_line` patterns cut one line
out of a multi-line statement, leaving an unbalanced call. Under the old code each returned:

    CAUGHT — "suite red — defended"

about a file the compiler refused to parse, with the suite never having run. That is not a
weak mutant, it is a broken one, and standard mutation testing excludes non-compiling mutants
as INVALID rather than counting them as killed.

THE FIX
`verdict_for` now runs `go build ./...` after applying the mutation and returns a new verdict,
MUTANT-BROKEN, when it fails. Reported, never folded into CAUGHT — the same rule the deadlock
gate and the NOTESTS case taught, and for the same reason: a broken mutation should show up as
something to FIX rather than inflating the number the instrument exists to keep honest.

    Fifth self-test case added, and VERIFIED TO BE A REAL GATE: with the build check
    neutered it fails with `got CAUGHT (suite red — defended)`, which is exactly the defect.
    A gate that has never failed is not a gate.

MUTANT-BROKEN also joins `_redraw_diff.DEAD` — a mutation the compiler rejects can neither
gain nor lose a defence across a redraw. No existing row carries the verdict, so that is a
no-op for every comparison already published and correct for the next sweep.
