WHY IT SURVIVES — DIAGNOSED, NOT ASSUMED
  Breaking the wrap should break the handler's 400. It does not, and the reason is that
  NOTHING UNWRAPS IT:

      models.go        return fmt.Errorf("%w: title is required", ErrValidation)
      tasks_handler.go if err := task.Validate(); err != nil {
                           writeError(w, http.StatusBadRequest, err.Error())

  The handler returns 400 for ANY error from Validate. It never calls errors.Is. So the
  wrap is decorative: `%w` and `%v` produce identical observable behaviour, and the suite
  is right not to notice.

  The spec promises this THREE times, which makes the gap worth stating precisely:
      "all matchable with errors.Is: ErrNotFound, ErrExists, ErrValidation"
      "returns a wrapped ErrValidation (use fmt.Errorf with %w)"
      "Task.Validate returning 400 with writeError on ErrValidation via errors.Is"

  Two different things are undefended here. The behaviour the handler produces (400) is
  correct by accident of "any error means 400". The CONTRACT the spec names — that the
  sentinel is recoverable with errors.Is — is not exercised anywhere, so a future handler
  that does branch on errors.Is would be built on an unpinned promise.

THE EDIT — pin the contract where it lives, not where it is consumed
  TestValidateWrapsErrValidation: call Task.Validate() DIRECTLY on an invalid task and
  assert errors.Is(err, ErrValidation). Assert on errors.Is, NOT on the message text — a
  message assertion passes with %v and pins nothing.

  Same recipe that closed the identical shape in tasks-api this morning
  (TestValidateWrapsErrInvalidTask), so this is a second data point for it rather than a
  new idea.

WHAT THIS MEANS FOR EVERYTHING CLOSED TODAY
  A closure is not durable. It is a property of the RUN that wrote the test, not of the
  spec that names it. Eight holes have been closed and verified, each on one artifact, and
  no single artifact carries all eight.

  Named tests compete for a budget. That reframes the programme from "accumulate closures"
  to "allocate a limited number of named tests", and it is the kind of constraint that is
  invisible while every closure is graded on its own fresh tree — which is exactly how all
  eight were graded.
