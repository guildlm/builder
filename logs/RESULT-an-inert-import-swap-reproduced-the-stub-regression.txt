⚠️ AND THE JSON TAGS ARE A REAL FUNCTIONAL BREAK, NOT A COSMETIC ONE
The spec never mentions tags — checked — so neither draw violates it. But the spec's own examples
POST `{"id":"cash","name":"Cash"}` and `{"account_id":"cash","amount":500}`. Go's encoding/json
accepts a case-insensitive match, so `id` still reaches `ID` untagged. `account_id` does NOT reach
`AccountID`: the underscore defeats case-insensitive matching, so that field silently stays empty.
Untagged, every posting in a transaction loses its account.

    A two-word transposition in a test file's import sentence broke the wire format of the API.
