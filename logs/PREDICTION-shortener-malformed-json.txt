THE HOLE
  handlers.go:26 — `Shorten` returns 400 when json.Decode fails. The spec promises THREE
  ways to earn a 400: "400 on malformed JSON or when the url field is empty or fails
  url.ParseRequestURI", and NAMES one test for them:
      TestShortenBadRequest: POST /shorten with `{"url":""}` -> 400.
  That covers the empty-field branch. Change the malformed-JSON branch to 404 and the
  suite stays green.

  This is the shape the sweep is best at and _named_test_audit is blind to: the named test
  EXISTS, so the audit is satisfied; it is the promise BEHIND the name that is short.

THE EDIT — both lessons from the previous two attempts applied
  NAME a test (attempt 1's failure was appending a clause to another test's description),
  and say what the model needs to know rather than what reads well to someone who already
  knows (attempt 2's failure was "the body is exactly ok" in a JSON-everywhere spec):

      TestShortenMalformedJSON: POST /shorten with a body that is NOT valid JSON —
      send the raw bytes `{"url":` (truncated on purpose, do not send `{}`) -> 400.

  "Truncated, not `{}`" matters: `{}` is valid JSON and would take the EMPTY-FIELD branch,
  which is the one already covered. Without that clause the model would very plausibly
  write a test that passes through the wrong branch and defends nothing — the same class
  of miss as decoding a plain-text body as JSON.
