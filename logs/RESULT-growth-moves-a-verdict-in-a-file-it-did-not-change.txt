AND THE MECHANISM IS THE INTERESTING PART
models.go differs between the two arms by EXACTLY TWO COMMENTS:

    + // Task represents a task with an ID, title, status, and project ID.

Comments cannot change behaviour. So the verdict change does not come from the mutated file at
all — it comes from the REST OF THE PROGRAM. The dose arm's handlers, store and tests differ,
and those differences decide whether a mutation inside models.go is observed.

    A MUTATION VERDICT IS A PROPERTY OF THE WHOLE PROGRAM, NOT OF THE MUTATED FILE.

    That is the sharpest thing this thread has produced for the campaign. Every row in the
    capstone is keyed (artifact, FILE, shape, ordinal) and read as a statement about that file's
    defences. This pair shows a row flipping from SURVIVED to CAUGHT while its own file is
    unchanged in every respect that a compiler can see. A flip attributed to a closure in file X
    can be caused by an edit that never touched X.
