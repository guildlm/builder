WHY IT CANNOT BE RUN
The experiment compares an assertion count between draws. Today established that such a count,
read off a tree, is a POST-REPAIR count. The two draws already on record:

    chain4   28 Jul, other server   asserts 1   deterministic fix only, converged   CLEAN
    chain5   29 Jul, server 4439    asserts 2   round 1 FAILED TO COMPILE, so the twins
                                                were first observed in round 2 — after a
                                                deterministic fix, a drained-body rebuild
                                                AND a model rewrite of that file    SPOILED

    So the existing pair cannot answer it, and neither can any new draw PAIRED WITH chain5.

And a fresh pair is not safe either. Whether a draw's twin values survive to be measured
depends on whether round 1 happens to compile — which is not controllable and not observable
in advance. A two-draw experiment has a real chance of producing two spoiled trees and a
confident-looking table that means nothing. That is the failure this whole day has been about.

    RUNNING IT NOW WOULD MOST LIKELY BUY ANOTHER UNINTERPRETABLE RESULT. Not a bad result —
    an uninterpretable one, which costs the same GPU hours and reads like evidence.

WHAT WOULD MAKE IT READY — three lines at the head of _fix_loop
`_fix_loop` (src/builder.py:5166) receives `written: dict[str, str]` — every generated file's
path and contents — BEFORE its first `check(out)` call. At that moment the dict IS the
as-drawn state, exactly, with no snapshot race and no filesystem walk:

    # At the head of _fix_loop, before `ok, output = check(out)`:
    (out / ".pre-fix.json").write_text(json.dumps(written, indent=1, sort_keys=True))

WHY A DOTFILE INSIDE THE TREE, and the alternatives that are worse
  * A SIBLING DIRECTORY (`<out>-asdrawn`) doubles the corpus on disk and adds another name
    every broad glob has to learn to skip — `_cross_draw` already needed teaching about
    `-prevN` today, and that skip was harmless only by accident.
  * A FILE UNDER logs/ makes the builder know about this repo's log layout, which it does not
    and should not.
  * `.pre-fix.json` travels WITH the tree, needs no configuration, and is invisible to every
    consumer in this repo: _hole_hunt walks `rglob("*.go")`, _twin_witness `rglob("*_test.go")`,
    _cross_draw `rglob("*.go")` plus copytree (which copies it harmlessly — `go test` ignores
    an unreferenced dotfile). Checked, not assumed.

NAMED `.pre-fix`, NOT `.as-drawn`, because `_fix_loop` has two callers: `build`
(generate-then-fix) and `maintain` (edit-then-fix). "As drawn" is wrong for the second and a
name that is wrong for half its callers is how a field gets misread later.

WHAT IT BUYS, beyond this one experiment
  * Every twin/seed/assertion quantity becomes measurable as-drawn, not post-repair. That is
    the measurement whose absence retracted two claims today.
  * `_provenance_census` stops depending on mtime heuristics. It currently matches build logs
    to trees by the newest .go file, cannot match 11 v4 trees at all because they were
    restored wholesale, and needed two bug fixes today to match the other twelve.
  * A diff of `.pre-fix.json` against the final tree says exactly what the fix loop changed —
    which is the question behind "did the repair work on the assertion, or mirror it?", still
    unidentifiable after a full day.

rather than in thirty minutes is also zero, and "near zero risk for zero benefit" is not a
trade worth making while a control arm is running. It lands when the draw does.
