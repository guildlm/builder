FINDING — a cold line and an unwritten test are the same gap, seen from two ends
================================================================================
2026-07-28 late. Model-free. Tools: _reachability.py, _named_test_audit.py + per-test dating.

THE CONVERGENCE

_reachability, walking coverage: taskapi's `internal/api/tasks.go:25`

    writeError(w, http.StatusBadRequest, "malformed request body")     COLD

Executed zero times by the whole suite.

The naming audit, walking the spec: taskapi's spec NAMES `TestMalformedJSON` — "POST
truncated bytes like `{"title":` (NOT an empty `{}`) -> 400" — and no test file in the tree
contains it.

Two instruments, opposite directions, same gap. One says the line never runs; the other says
the test that would run it was never written. Neither knew about the other.

IT SURVIVED TWO DRAWS — AND A THIRD OVERTURNED THAT (see the update at the end)

    the name entered specs/taskapi.yaml      2026-07-11 15:19
    generated/taskapi-v4 was drawn           2026-07-26 16:09
    generated/taskapi-chain was drawn        (also absent)

Fifteen days, two independent draws, and the test was written in neither. At this point I
took that for a spec defect. It was not — the third draw wrote it, and the section at the
end of this file retracts the conclusion. The dating below is still what separates a real
absence from a clock; what it cannot do is turn TWO absences into a property of the spec.

Compare taskapipro's TestListSorted — the loss this repo's own naming audit was BUILT to
catch, absent from draw 1 and, measured just now, present in draws 2 and 3. I checked that
one rather than assuming, and should have read it as the warning it was.

WHY NEITHER TOOL SAID SO ON ITS OWN

_named_test_audit refuses to score an artifact when any file the spec DECLARES is missing
from the tree, on the reasoning that a run in flight looks exactly like a model refusing to
write. That is correct and its docstring argues it well. But every -v4 tree now lacks
middleware_chain_test.go, because the Chain closure was added to the specs after those trees
were drawn — so the audit skipped taskapi, taskapipro, taskflow, usersapi and workapi
entirely. The artifacts under active campaign work are exactly the ones it could not see.

The fix is not to loosen the refusal, it is to make it PER TEST. Dating each missing name
against the artifact's build time separates the two populations cleanly:

    41 spec-named tests absent from their -v4 tree
    29  SPEC AHEAD — the name was added after the tree was drawn. Not a finding; it is
        the campaign working as intended, and scoring it would manufacture 29 failures.
    12  named BEFORE the draw and still absent
        10  all of them tasks-api-noshadownudge, an experimental variant whose tree is
            incomplete and whose suite does not build. A broken artifact, not a result.
         1  taskapipro TestListSorted — self-healed in later draws, verified.
         1  taskapi TestMalformedJSON — the real one.

Yield: ONE candidate — and, after the third draw, ZERO confirmed spec defects. That is
still worth writing down against the 41 an unfiltered version reports, because 29 of those
are only a clock. But the honest final count for tonight is that this audit produced no
defect, and the value it delivered was the per-test dating method, not a finding.

WHAT IT MEANS FOR THE CAMPAIGN'S CENTRAL CLAIM

The rule this week has been "an invariant with its own named test holds — 30 of 30". That
number is about closures I WROTE AND THEN GRADED. It is not the base rate for naming. Here
is a test named in a spec for fifteen days, in an entry that names nine others, and the model
did not write it twice running.

    Naming is necessary and it is not sufficient. A named test can simply not be written,
    and nothing in the green-suite / coverage / mutation stack can see that: a test that
    was never written lowers no coverage number and survives no mutation, because it is
    not there to fail.

That is the third distinct failure mode for a named invariant, alongside the two already
recorded — the test written but its assertion evaporated (2/2 SURVIVED), and the test
written with a witness that cannot discriminate (bitset asserting at 200 while the flip
moves at 128). This one is the plainest and the only one no runtime instrument can reach.

UPDATE, SAME NIGHT — THE THIRD DRAW WROTE IT, AND THAT CHANGES THE CONCLUSION

taskapi's third draw (generated/taskapi-chain2, read while the run was still finishing, so
provisional until the gates land) DOES contain TestMalformedJSON, in
internal/api/router_test.go.

So the sentence is not dead. It is UNRELIABLE. Absent in taskapi-v4, absent in taskapi-chain,
present in taskapi-chain2 — the same shape as taskapipro's TestListSorted, absent in draw 1
and present in draws 2 and 3. Two independent named tests, both intermittent.

That kills the conclusion this file was heading toward. I had written that a third absence
"would earn a rewrite rather than a repetition", implying the spec language had failed. It
had not. What failed is the inference from a single artifact:

    A named test missing from ONE draw is not evidence the spec failed to ask for it.
    It is one sample of a stochastic writer, and this corpus has now produced two named
    tests that appear in some draws and not others.

The claim that survives is the narrower one: naming is NECESSARY AND NOT SUFFICIENT, and no
runtime instrument can see the difference, because a test that was never written lowers no
coverage number and survives no mutation. What does NOT survive is the implied remedy.
Rewriting a sentence that works two draws in three would have been fixing the wrong thing —
and I would then have "confirmed" the fix by drawing again and watching it appear.

The right remedy is the audit run PER DRAW, which is what _named_test_audit is for, and
exactly why it needs per-test dating: to say "this draw missed one" without saying "this
spec is broken".

WHAT WAS ACTED ON, AND WHAT WAS NOT

The spec was NOT edited, and that turned out right for a better reason than the one I had:
I withheld the edit only because the draw was in flight and editing would make the artifact
unattributable. Had the draw finished ten minutes earlier I would have rewritten a sentence
that works.

Also confirmed in the same draw, and the reason it was worth watching: BOTH halves of the
empty-list mirror were written — TestListEmptyIsEmptyArray in router_test.go and
TestProjectListEmptyIsEmptyArray in projects_test.go. First mirror in this campaign specified
before either half was found open, and both halves took.
