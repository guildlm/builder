  separate "naming works" from "that spec had a good day".

WHAT IS ALREADY VISIBLE AT N=4
  THE CLOSURE ITSELF IS NOT THE VARIABLE. Both specs wrote the test, both assert the order,
  both catch the mutation. The prediction I was least sure of — that the model would assert
  the ORDER rather than the status, given that prose explaining why a WEAKER assertion is
  insufficient has the worse record here — has now held twice.

  THE RENDERING VARIES, THE CONTENT DOES NOT. usersapi wrote `strings.Join(order, ",") !=
  "first,second,handler"`, exactly as dictated. taskflow wrote an element-wise compare against
  a `want` slice — stronger than dictated, and it defeated the run script's grep for the
  literal string. Two renderings, one contract, both catch the flip. Worth remembering the
  next time a spec dictates a FORM: the model honours the assertion's MEANING more reliably
  than its syntax, and a grader keyed to syntax will lie.

  THE COST IS NOT IN THE EDIT. 21,676s against 546s for the same one-file, one-test addition —
  a factor of forty. Whatever taskflow spent six hours on, it was not this test: it wrote it,
  correctly, and dropped nothing. Two specs, two currencies, and neither paid in dropped tests.

  NEITHER SPEC DROPPED A TEST. The corpus record says taskflow "pays for a harder spec in
  DROPPED TESTS where shortener pays in TIME". Both of these added a file entry and lost
  nothing; taskflow paid in time, which is the other spec's currency. That claim is now
  narrowed twice over and should not be quoted as it stands.

WHERE THE SIX HOURS WENT — counted, not guessed
  The open question was whether taskflow's 21,676s belongs to taskflow or to the edit.
  Counting model calls in the three logs answers it, and the answer is neither size nor the
  edit:

      spec       files  rounds  resolved by          model fix-calls  wall     tree
      usersapi     9      0     nothing to fix              0           546s   GREEN
      taskapi     18      1     DETERMINISTIC GATES         0          1532s   GREEN
      taskapipro  21      2     DETERMINISTIC GATES         0          2760s   GREEN
      taskflow    16      8     model, and never            84         21676s  RED

  taskapi has the MOST files of the three and cost zero fix-calls: "converged to green after
  fix round 1 (deterministic)" — three gate repairs, no model round-trip. taskflow spent 84
  model fix-calls across eight rounds against a budget of five and ended red.

  So the cost is the FIX LOOP, and the fix loop is cheap exactly when the deterministic gates
  can resolve it. That is the recorded ordering lesson — deterministic gate first, model for
  the residue — with a number on it for the first time: the difference between a spec whose
  failures fall inside the gate chain and one whose failures do not is 0 versus 84 calls, and
  40x wall clock.

  It also settles the attribution: the edit adds one file to every spec, and two specs that
  received it paid nothing at all.
