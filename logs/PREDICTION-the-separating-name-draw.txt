WHAT THE RULE ACTUALLY IS
Not "keep test names uniform within a file". That is the pattern I first wrote down at 11:04
and it is now falsified as a cause. The rule is narrower and more useful:

    Do not give a test a name whose prefix points at a group where a test of that
    description already exists.

TestListProjectsSorted announced itself as a TestList* test — the tasks group, in the sibling
file — and TestListSorted was already there, asserting the tasks sort. A test that looks like
one already written is dropped, and dropping it is locally reasonable. TestSortedProjectList
announces nothing: TestSorted names no group, so it collides with nothing and survives its
own oddity.
