AN INCIDENTAL RESULT, AND IT IS A NICE ONE
The twelve inert lines are an argument AGAINST shadowing `t` in a test — "NEVER NAME A LOCAL
VARIABLE t ... SHADOWS that handle for the rest of its scope". The draw shadowed `t` anyway:

    renamed the loop variable shadowing t *testing.T in taskflow_test.go

So did the control, which never saw those lines. Both draws needed the same gate, in the same
file. The prose did not prevent the exact defect it describes — and it was not supposed to,
since it was chosen to be INERT, but it is worth recording that a spec paragraph arguing
against a specific mistake did not stop that mistake in the very same draw.

    It also confirms the lines really are inert in the intended sense: they changed four
    unrelated implementation files and did NOT change the one behaviour they argue about.
