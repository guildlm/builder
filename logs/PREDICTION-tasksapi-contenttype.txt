WHAT I DID NOT PREDICT — THE SITE MOVED FILE
  Every earlier tasks-api tree put writeJSON in handlers.go, so I graded with
  --file=handlers.go and got NOAPPLY. The behaviour had not vanished; this tree put
  writeJSON in task.go, and graded there it reads CAUGHT. The assertion moved too — the
  named test landed in store_test.go, not handlers_test.go.

  The grader was right to refuse, but a bare NOAPPLY reads like "the mutation does not
  apply to this artifact", which would have retired a closure that had in fact landed.
  _hole_closed now says so out loud when the pinned file holds no site and another file
  does. Shown to fire on this artifact, and shown NOT to fire when the pin is correct.

  The pinned --file is a memory of the LAST tree. A regeneration is free to move the site,
  and this one did — which is one more reason the row file, not my recollection, is the
  record.

CORRECTION, same hour — "same fleet" is not something I can claim

  was never committed, and the artifact was replaced), so its invocation exists only in my
  summary of it. It may have run base-only, or with a different member.

  What survives the correction: the same spec, on the same base model, converged in 288s
  with ONE deterministic fix round and zero model calls spent on the compile error, where
