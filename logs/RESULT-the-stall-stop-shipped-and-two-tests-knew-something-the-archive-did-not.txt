THE RULE
`_fix_loop` stops when the error surface has been IDENTICAL for `_STALL_RUN` (=3) rounds in a
row. It falls through to the final deterministic pass, so this shortens the LLM fix loop rather
than abandoning the build.

RUN, NOT REPEAT — the predicate matters and the old guard has the other one
The pre-existing guard fires only PAST the flat budget and only on set membership. `A B A B`
repeats at round 3, and stopping there kills a build whose fixer is still moving it, just in a
circle it might yet escape. Only an unbroken run says it has stopped. Both the tool and the
harness test pin the alternating case, because it is the one an eyeballed table gets wrong.

⚠️⚠️ THE PART THE MEASUREMENT COULD NOT HAVE TOLD ME, AND WHAT FOUND IT
The first implementation was a bare run-of-3. Full suite: 448 passed, 2 FAILED —
`test_a_widened_file_escalates_too_or_impl_bugs_are_unreachable` and
`test_escalating_a_widened_impl_converges_the_build`.

Not a test artefact. `_FLEET_ESCALATE_AFTER` is 2, and a WIDENED file only enters the fix
targets on round 2, so it escalates on round 3 — and a run-of-3 stops the loop at the START of
round 3, pre-empting it by exactly one round. That path is load-bearing:
logs/FINDING-escalation-granularity.txt took shortener from 3/3 GREEN to 2/3 RED when widened
files were denied escalation.

THE ARCHIVE IS SILENT HERE, AND I CHECKED ONLY BECAUSE THE TESTS FAILED:

    logs containing an escalation at all      1  of 785
    escalations followed by a green           0

So "K=3 kills no green" was measured over a population where the fleet was effectively OFF. The
table is not wrong; it has nothing to say about this. A null is a claim about what the
instrument could resolve, and this instrument could not resolve the escalation path at all.

📌 THE ORDER IS THE LESSON. 133 segments, an out-of-sample split and a clean separation still
did not surface a defect that two existing tests found in 127 seconds. The measurement told me
the threshold was safe for the builds in the archive; only the tests told me the archive was
not the population.

THE FIX, AND WHY IT IS THE RIGHT SEMANTICS RATHER THAN A PATCH
The counter means "same surface, SAME FIXER". An escalation changes the fixer, so it resets the
run exactly as a changed surface does — the new member has not had one round judged yet.

    ✓ Escalations are finite (the fleet runs out) and `max_fix_rounds + _EXTENSION_ROUNDS`
      still caps everything, so the reset cannot disable the guard. Pinned by a test.
    ✓ The reset only ever makes the guard fire LESS than the simulation did, so the measured
      damage remains an upper bound: greens killed <= 0. The saving is the number that drops,
      and only on fleet-enabled builds — 1 in 785 of the archive.

CONTROLS, because a guard that never fires and a guard that always fires both look green
    guard deleted        → 4 of 10 stall tests FAIL (exactly the four that assert it fires;
                           the four asserting silence pass either way, which is correct —
                           they cover the false-positive direction)
    reset deleted        → the new escalation test AND both existing escalation tests FAIL
    threshold parametrised over K=2,3,4 → catches a guard hardcoded to 3, which every other
                           test in the file would have passed
