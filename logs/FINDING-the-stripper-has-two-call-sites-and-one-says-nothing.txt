WHAT IS ACTUALLY THERE
    strip_redeclarations is called from TWO places:

        _sample_clean()         ~5223   logs "stripped redeclared symbols from {what} candidate"
                                        — announces that it happened, names NOTHING
        _sample_verified_fix()  ~5306   `cand = strip_redeclarations(cand, sibling_decls)`

    The queued one-liner covers the first. The second is the FIX path — the one that runs repeatedly
    inside the loop, on every fix candidate — and today it deletes declarations from model output
    and says nothing whatsoever.

HOW MUCH IS AT STAKE, measured on the archive rather than guessed
        log files in logs/                                   779
        log files containing the site-A message              276     (35%)
        site-A stripping events across those logs            526
        site-B events                                        UNMEASURABLE — it prints nothing,
                                                             which is precisely the finding

    So 526 times this harness deleted declarations from a model's output and recorded only that it
    had done so. The names are gone. And the count for the busier of the two sites cannot be
    recovered at all, because the only evidence it ever ran would have been a log line it does not
    write.

    ⚠️ 276 of 779 is LOG FILES, not builds. The archive segments to ~654 builds and a log file is
    not one-to-one with a build. The honest statement is "a third of the log files in this
    archive", not "a third of builds".

WHY THIS MATTERS BEYOND TIDINESS
    The stripper is a DETERMINISTIC EDIT to model output, applied before the candidate is judged
    clean. When a file ships EMPTY — the consolidation defect this whole campaign is chasing — one
    of the live hypotheses is that the stripper removed what the model wrote because a sibling had
    already claimed the names. Today that hypothesis cannot be tested against the record, because
    the record does not contain the names.

    ⚠️ AND IT STILL CANNOT BE TESTED RETROSPECTIVELY AFTER THIS FIX. Logging from now on recovers
    nothing about the 526 events already past, or about today's parity arms. This buys future
    evidence only, which is why it sits behind the two fixes that produced evidence immediately.
